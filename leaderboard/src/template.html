How a bug becomes a score

The method matters more than the leaderboard. Here is what each score rests on.

  1. Find a real fix

    Take a merged pull request that closed a GitHub issue and changed a test. The issue text becomes the bug report; the fix and its tests become the answer key.

  2. Prove it is a fair task

    Before the fix, the new tests must fail. After it, they must pass. Each task is run three times to throw out flaky tests. A task that fails either check is rejected and logged.

  3. Let the agent try

    The agent gets the issue text and the code as it was before the fix, with no git history. Same instructions, {{turns}} turns and {{minutes}} minutes for every model. Any test file it edits is put back.

  4. Score the patch

    The hidden tests are added and run. The bug counts as fixed only if every target test passes and no test that used to pass now fails.

How each attempt is counted

Fixed
All target tests pass and nothing else broke.
Not fixed
The patch ran but a target test still fails, or something else broke.
Timed out
The tests didn't finish in time. Counts as not fixed.
Patch did not apply
The diff was malformed. Counts as not fixed.
Excluded
Our own failure, such as a billing error or a broken install. It is never held against a model. {{excluded_note}}

Why zero isn't a bug in the scoring

A run of zeros looks suspicious, so we checked. The scoring accepts the real human fix on every task and rejects an empty patch on every task. We also traced one task where a local model scored a fix once in a timing test, then failed the same task ten times. The scoring was correct: that task checks two near-identical test variants, the human fix passes both, and a partial fix can pass only one. The one-off pass was most likely run-to-run variation in local inference. Small local models scoring near zero on hard, real bugs is a plausible result, not a broken pipeline.

We also tried a smarter agent

The plain agent types one shell command per turn. We built a second agent with real tools (read, search, edit, run the tests) and language-specific instructions, using LangGraph. On 5 Python tasks with Qwen3 14B it fixed none, {{lg_note}}

That is one model on five tasks, so it is a note and not a finding. The work is in a separate project, so nothing here changes the main benchmark.

Check our work

The code, tasks and results are open. You need Docker, uv, and either Ollama or an API key. Nobody outside this project has run these yet.

# the gold patch must fix every task, an empty patch none
uv run python scripts/run_gate.py

# run a model on every task, 10 tries each (resumable)
uv run python scripts/run_driver.py \
  --models ollama_chat/qwen3:14b \
  --instances all --repeats 10 \
  --out results/my_run.jsonl

# fix rate and pass@k with error bars
uv run python scripts/compute_stats.py \
  --in results/my_run.jsonl --k 5
